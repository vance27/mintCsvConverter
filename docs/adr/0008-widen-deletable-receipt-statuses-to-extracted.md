# Widen deletable receipt statuses from FAILED/CANCELLED to include EXTRACTED

[ADR-0002](0002-cancelled-status-and-receipt-delete.md) scoped hard-delete to `FAILED`/`CANCELLED` only, reasoning that `EXTRACTED` (and `SUBMITTED`) receipts "carry real data that must never be silently destroyed." The multi-model comparison workflow ([ADR-0007](0007-per-upload-model-selection.md)) broke that assumption: `PriceObservation`/`ItemSplitDefault` rows are written the moment a receipt reaches `EXTRACTED` (inside the same transaction, per `ingest.ts`), not at submit time — so a "losing" comparison model, once extracted, would permanently pollute that item's real price-history and learned-split defaults with no way to remove it, even though it was never submitted.

Decided: extend deletability to `EXTRACTED` too, narrowing the truly-protected line down to just `SUBMITTED`. This isn't a reversal of ADR-0002's reasoning so much as a correction to its scope: this app already treats **submit**, not extraction, as the one true confirmation point (that's when `ItemSplitDefault` gets upserted "for real," per the existing "latest correction always wins" rule elsewhere in the codebase) — so `EXTRACTED`-but-unsubmitted data was never actually meant to be permanent. ADR-0002 just hadn't yet hit a case that depended on that distinction.
