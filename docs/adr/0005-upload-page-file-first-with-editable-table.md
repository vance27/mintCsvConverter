# Upload page becomes file-first, with Store/Payer as an editable per-row table

The Upload page currently asks for Store/Payer up front (one shared value for the whole batch), then files are chosen and uploaded immediately — no review step in between. That's inverted from how the rest of this app works (Import and Sync both stage first, then let you review/edit before any commit), and it forces one Store/Payer value onto every file in a batch even when a batch is meant to hold several genuinely distinct receipts (one `Receipt` row per file is already correct behavior — each file may itself be 1..* pages, handled in one extraction call — batching just lets you queue several receipts in one action).

Considered keeping one shared Store/Payer field per batch (simplest, no API change) — rejected because Store also selects the extraction prompt (see [ADR-0004](0004-extracted-store-reconciliation.md)) and must match a vendor-list entry (see [ADR-0003](0003-receipt-upload-store-and-payer-fields.md)), so a batch that isn't uniformly one store would silently mis-extract whichever files don't match the one shared value.

Decided: files are picked first, then shown in an editable table with per-row Store (`Autocomplete`/`freeSolo`) and Payer (`Select`) columns, defaulting to the *last values used* (sticky, e.g. `localStorage` — not a hardcoded default like today's `'Costco'`/`'Brian'`, and not blank-forcing-a-choice-every-time). Nothing is queued for extraction until an explicit submit action, at which point each row becomes its own `Receipt`, same as today's per-file behavior. `POST /api/uploads` needs to accept per-file store/payer instead of one shared pair for the whole request body.
